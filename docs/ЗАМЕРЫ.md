# Замеры: где была задержка

Машина: Unitree Go2, борт NVIDIA Orin NX, 4 ядра. Интернет через 4G-роутер,
телефон и ноутбук ходят к роботу по Tailscale.

## 1. Видео забивало канал

Телефон смотрел два полных потока. Замер пинга до телефона с робота:

| | пинг |
|---|---|
| видео закрыто | 36 мс |
| две камеры открыты | 600–1066 мс |

Отдача 4G не тянула 3.4 Мбит/с, и в очереди стояло всё остальное: команды
джойстика, рация, кнопки. Лечится не «оптимизацией интерфейса», а битрейтом.

Лёгкие копии 640×360 аппаратным кодировщиком:

| поток | было | стало |
|---|---|---|
| штатная камера Go2 | 1350 кбит/с | 205 кбит/с |
| USB-камера | 2051 кбит/с | 377 кбит/с |
| вместе | 3.4 Мбит/с | 0.58 Мбит/с |

Процессор на обе копии: 3.3% и 5.6% (декодирование и кодирование железом).
Для сравнения, программное сжатие 1080p с USB-камеры занимает целое ядро.

Температура борта при этом выросла с 61 до 67 °C.

## 2. Лишние 100 мс на каждой команде

Замер с ноутбука при пинге 50 мс: запрос к службе управления шёл 145–186 мс.
Изнутри робота та же ручка отвечает за 2.5 мс, а посредник ни при чём —
прямой запрос мимо него давал те же 150 мс.

Причина — алгоритм Нейгла. Сервер отправляет заголовки и тело ответа разными
кусками, и второй ждёт подтверждения первого: лишний круг по сети на каждую
команду. Лечится одной строкой в классе обработчика:

```python
disable_nagle_algorithm = True
```

Проверено A/B: копия службы с этой строкой на запасном порту, та же связь,
тот же момент времени.

| | без правки | с правкой |
|---|---|---|
| запрос к пульту | 145–186 мс | 27–56 мс |
| команда движения через https | ~150 мс | 44–56 мс |

Теперь время команды равно пингу, лишнего нет.

## 3. Чего замер не показывает

Задержку самой картинки (камера → экран телефона) мы измеряли иначе: часы с
десятыми долями секунды на экране, камера робота смотрит на них, разница
между кадром и живыми цифрами — задержка всего тракта. Способ грубый, но
честный, и не требует ничего, кроме второго экрана.

## Как мерить у себя

```bash
# пинг до узла в тайлнете
tailscale ping -c 6 <адрес>

# время ответа службы по УЖЕ открытому соединению (как в браузере),
# а не по новому: новое платит рукопожатием TLS, у нас это 126 мс
U=https://<адрес>:9996/ctl/state
curl -sk $U $U $U $U -o /dev/null -w '%{time_total}\n'

# битрейт потоков
curl -s 127.0.0.1:9997/v3/paths/list   # основной раздатчик
curl -s 127.0.0.1:9994/v3/paths/list   # лёгкий
```
